# VS Code: план и журнал выполнения

## Цель и принятые решения

VS Code становится основным интерфейсом: редактирование `.pk`, LSP, историческая нотация рядом с исходником и весь существующий монитор исполнения. Python остаётся владельцем синтаксиса, типов и генерации IL; Worker/Runtime — исполнения и памяти. WPF сохраняется до проверки функционального соответствия. Не добавляем второй анализатор в TypeScript, новые операции языка или полный отладчик DAP.

Пользователь разрешил реализацию всего плана и промежуточные отчёты по срезам. UI и Computer Use не запускать: проверять протоколы и логику без окна, визуальную проверку передавать пользователю. Сохранять ручные изменения, tex/, habr/ и исторические материалы.

## Инварианты

- Источник истины для языка — Python AST/Analyzer; для нотации — notation.project.
- Редактор хранит версионированные документы; устаревшие ответы не публикуются как текущие.
- Запуск связан с неизменяемым снимком исходника, а не с редактируемым буфером.
- Программа и диагностический вывод отделены от сообщений управления.
- Каждый запуск имеет свою кучу и процесс; остановка одного не влияет на другие.
- Неизвестные позиции ошибок не извлекать из произвольного текста.
- Не обещать проверку UI или платформ, которые не проверялись.

### 0.1.2 — позиция пошагового исполнения

На паузе выбранного запуска автоматически открываются снимок исходника, нотация и монитор в трёх группах. Код прокручивается к текущей строке; в нотации выделяется ближайший соответствующий оператор, а не все внешние блоки. Подсветка привязана к URI и версии снимка, снимается при продолжении/завершении. Фоновые запуски не перехватывают просмотр выбранного. Визуальную проверку выполняет пользователь; UI не запускался.

### 0.1.3 — монитор снизу, повторный запуск, задержка

Монитор перенесён из редакторской вкладки в нижнюю панель VS Code; сверху остаются код и нотация. «Новый запуск…» в мониторе открывает параметры выбранной программы: аргументы, режим, размер кучи, задержку. Предзаполнены значения выбранного запуска. Компилируется текущий буфер исходного файла (включая несохранённые изменения), предыдущий запуск и его снимок остаются в истории. Отмена диалогов не запускает программу.

При задержке > 0 код и нотация следуют снимкам исполнения; позиция обозначена как последняя полученная. На паузе показывается точное место остановки. После завершения подсветка снимается. Транспорт и Runtime не изменены.

### 0.1.4 — форма запуска и типовые подсказки

Команда запуска из редактора теперь выбирает файл и открывает форму в мониторе. Аргументы JSON, куча, задержка и пошаговый режим редактируются прямо там; кнопка «Запустить» собирает текущий буфер. Поля не перезаписываются снимками памяти. Задержка уже работающей программы — отдельное управление. Ошибки формы показаны под параметрами, без цепочки диалогов.

Исходный файл не переименовывается: для выполнения открывается отдельный документ только для чтения «имя — снимок #N.pk». Он содержит текст, использованный при сборке. Исходник можно редактировать независимо; следующий запуск берёт его актуальный буфер.

LSP сохраняет уже определённые типы при семантических ошибках в других выражениях. Hover показывает тип в синтаксисе .pk и структуру S; работают переменные, поля, индексы, результаты выражений и объявленные планы. Автодополнение включает типы, переменные, номера полей записи, разыменование @ и шаблоны вызовов. При вводе аргументов появляются сигнатуры с текущим параметром. Ctrl+Space вызывает дополнения вручную.

Для незавершённой строки применяется ограниченное восстановление: одна строка временно исключается только для подсказок, без удаления границ блоков. Такие типы подписаны как полученные по завершённой части кода. Проверка ошибок и сборка всегда работают с исходным текстом. Для произвольно повреждённых заголовков/вложенных блоков восстановление не гарантируется.

Проверка 0.1.4: 6 проверок Python LSP и 9 проверок JavaScript прошли; VSIX собран. Сценарии .NET в этом срезе не повторялись: Runtime не менялся. UI не запускался. Для установки обновить VSIX и перезагрузить окно, чтобы перезапустить LSP из текущей editable-установки.

### 0.1.5 — исходник и карточки типов

При совпадении текущего текста исходника с запущенной версией выполнение подсвечивается в исходном файле. При изменении буфера подсветка в нём сразу снимается и открывается снимок для отображения исполнения. Сравнение учитывает несохранённые изменения. При точном возврате к запущенному тексту исходник снова подходит для подсветки. Несколько запусков не смешивают подсветку: показывается выбранный.

Hover использует Markdown: сигнатура в блоке кода .pk, определение типа, таблица полей и структура S. Сохраняются явно написанные алиасы и их происхождение через копирование переменных/доступ к полям/результат плана. Совпадение структур само по себе не назначает алиас. Цепочка простых алиасов раскрывается, ссылки в рекурсивных типах не разворачиваются бесконечно. Ссылки «Перейти к типу» открывают определения в редакторе, где можно продолжить наведение по вложенным типам. Подсказки дополнения используют те же карточки и имена алиасов. Оформление встроенного hover задаётся темой VS Code; подписи и блоки кода имеют разные роли и шрифты.

Проверено: 8 Python-проверок LSP и 10 JavaScript-проверок без UI, включая ссылки на определения, цепочки алиасов, поля, копирование, отсутствие ложных алиасов, исходник/редактирование/снимок/возврат текста. Runtime не менялся, сквозные .NET-сценарии повторно не запускались. Визуальная проверка — пользователю.

### 0.1.6 — раскрытие типов в hover

Типы полей и ссылки «Раскрыть тип» обновляют содержимое той же подсказки. Появляются «Назад» и «К исходной подсказке». История ограничена 32 карточками, рекурсивные ссылки раскрываются только по нажатию. Таблица аргументов и результатов в hover объявлений планов содержит те же раскрываемые типы. «Открыть определение в редакторе» остаётся отдельной ссылкой.

Адаптер VS Code использует [command URI в hover](https://code.visualstudio.com/api/extension-guides/command#command-uris) с разрешением только собственной команды. Карточка обновляется у исходного символа через hide/show hover; каретка устанавливается на исходную позицию наведения, без перехода к объявлению. Смена версии документа или места наведения отменяет устаревшие ответы. Сервер отдаёт карточки типов через plankalkul/type.

Проверено без UI: 9 Python-проверок LSP и 12 JavaScript-проверок, включая ссылки типов в объявлениях функций, поля вложенных записей, переходы/возврат в hover и отклонение устаревшего ответа. Runtime не менялся, .NET повторно не запускался. Реальное поведение popup и кликов необходимо проверить пользователю после обновления VSIX и перезагрузки окна.
