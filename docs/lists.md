# Списки, составные значения и стандартные планы

Списки заменяют прежнюю модель массивов. `n x T` — список фиксированной длины, `* x T` — переменной. Запись `(T, U)` имеет фиксированную форму. Список однороден, запись может содержать разные типы. Обе конструкции допускают вложенность. Они хранятся в управляемой памяти .NET независимо от ручной `@`-кучи.

```text
int = 32.0
[4, 3, 4] => Z0
[] => Z1[:* x int]
(7, [1, 2]) => Z2
Lz(Z0, [9]) => Z0
```

При выводе типа переменной длина списка становится переменной, в том числе во вложенных структурах. Длина самого литерала известна анализатору, поэтому `[1,2] => Z0[:3 x int]` отвергается сразу. Присваивание списка с неизвестной длиной в фиксированный проверяет длину во время выполнения. Пустой литерал получает тип из назначения, параметра или другого операнда Lz; без контекста это ошибка.

Порядок и повторы сохраняются. `=` и `!=` сравнивают составные значения рекурсивно, без упорядочивания. Присваивание, аргументы и результаты имеют семантику значения: вложенные списки копируются. Изменение локального параметра V не меняет аргумент вызывающего плана. Поля `@T` сохраняют идентичность ссылок, объекты за ними не клонируются.

Компоненты выбираются прежними путями: `Z0[i0]`, `Z0[(i0 + 1)]`, `Z0[i0.1]`. Запись меняет существующий элемент; выход за границы не расширяет список. Индекс должен быть целочисленным скаляром до 64 бит. Размер списка и N представлены Int32; фактический предел зависит от доступной памяти и ограничений CLR-массивов. Это не лимит `--heap-size`.

Начальные скаляры равны нулю, ссылки — NIL, переменные списки пусты. Фиксированный список содержит заданное число рекурсивно инициализированных значений; записи инициализируются по полям. Элементы вложенных списков не разделяют изменяемое хранилище.

| Операция | Результат / правило |
|---|---|
| `N([7,8])` | `2`, число элементов верхнего уровня |
| `Lz([1,2],[3])` | `[1,2,3]` |
| `Qz([1,2],[7,8])` | `[(1,7),(2,8)]`, длины обязаны совпадать |
| `Sp([(1,7),(2,8)],1)` | `[7,8]`, номер поля — статическое целое |
| `Nr([7,8])` | `[(0,7),(1,8)]` |
| `insert([2,3],1,9)` | `[2,9,3]`, позиция от 0 до N включительно |
| `remove([2,3],0)` | `[3]`, позиция от 0 до N исключительно |
| `reverse([2,3])` | `[3,2]` |

Lz и Qz принимают ровно два списка, Sp — один номер поля. Для добавления отдельного элемента используется `[значение]`. Все преобразования возвращают новое значение; `Lz(Z0,Z0) => Z0` удваивает прежнее содержимое. Не вводятся множества, автоматическое удаление повторов, отдельные типы отношений/цепей/колец, W6 или пользовательские ограничения типов.

## Библиотека и внутренние шаблоны

N и Lz — встроенное ядро. Остальные шесть операций реализованы в `src/plankalkulsharp/stdlib/*.pk`: циклы, компоненты и присваивания обрабатываются обычным компилятором. Имена операций зарезервированы; пользовательский план не может незаметно подменить стандартный.

`stdlib/catalog.json` описывает параметры типов, статические параметры и контракты. Сигнатура берётся из самого `.pk`. Общий алгоритм сопоставляет её с аргументами и ожидаемым результатом, связывает параметры типов и рекурсивно подставляет их в AST. Повторные вхождения параметра проходят обычную проверку совместимости. Ключ специализации включает имя, конкретные типы и статические параметры; внутри модуля одинаковые специализации переиспользуются. Их внутренняя идентичность не занимает пользовательские номера P.

Например, для `reverse(V0)` с `V0[:* x (32.0,64.0)]` параметр `item` становится `(32.0,64.0)`. Создаётся типизированный план с той же логикой `.pk`, а не C#-реализация reverse. Для нового обычного шаблона достаточно файла `.pk` и записи каталога с перечнем параметров типов. Он может вызывать другие стандартные планы. Новому имени в каталоге следует соответствовать обычному идентификатору со строчной буквы. Внутренний префикс __stdlib_ зарезервирован. Публичный синтаксис пользовательских обобщений пока отсутствует.

Например, `last.pk` может содержать:

```text
P0 (V0[:* x element]) -> R0[:element]
    V0[(N(V0) - 1)] => R0
END
```

Запись `"last": {"types": ["element"]}` в разделе plans каталога подключит его без новой ветви анализатора или генератора. Пустой аргумент будет отклонён проверкой компонентного доступа при исполнении. Это пример расширения каталога, он не входит в поставляемые операции.

Контракты каталога поддерживают равенство длин и допустимую позицию. Известные нарушения проверяются анализатором, остальные — перед вызовом, после однократного вычисления аргументов слева направо. Это внутренние проверки стандартных операций, не система пользовательских ограничений типов. Для Sp статический параметр выбирает поле связанного типа записи и подставляет его номер в компонентный маркер шаблона. Добавление нового вида статического параметра или контракта потребует расширения общего механизма.

В модуль включаются используемые специализации и зависимости. Исходники `.pk` и каталог входят в wheel. Хеш библиотечных ресурсов находится в метаданных IL и меняет ключ кеша модуля даже при изменении комментариев библиотеки; общую Runtime из-за изменения `.pk` пересобирать не требуется.

Копирование сейчас непосредственное, без copy-on-write. Библиотечные циклы строят результат последовательными Lz, поэтому возможны квадратичные затраты времени и копирования. Это прозрачная исходная реализация, а не обещание производительности для больших списков. Списки не отображаются в инспекторе ручной кучи.

## Ввод, вывод и наблюдение

```powershell
uv run plankalkulsharp run examples/lists.pk -- '[2,3,4]'
```

Каждый аргумент CLI — отдельное значение JSON. Списки и записи передаются JSON-массивами; объявленные типы задают их смысл, вложенность и фиксированные длины. Числа разбираются непосредственно в Int32/Int64, без промежуточного double. Для бита допустимы 0/1 и JSON true/false. Ссылки во входах и результатах главного плана запрещены. Пропущенные аргументы получают начальное значение своего типа, как прежде скалярные получали ноль.

В поле аргументов WPF значения разделены пробелами, например `5 [1, 2, 3]`; пробелы внутри списка допустимы. Каждый результат печатается отдельной строкой. Составные значения — JSON-массивы, биты — 0/1. Это формат ввода/вывода, не синтаксис выражений `.pk`.

Нотация показывает литералы, операции и переменную длину `¤ × T`. Кнопка «Стандартные планы» открывает исходники шаблонов и проекцию специализированного AST. Параметры типов и статическое поле явно поясняются. В библиотечных циклах остаются контрольные точки паузы, задержки и остановки; их позиция `(0,0)` не подсвечивает строку пользовательского файла. Ошибки компонентного доступа внутри библиотеки содержат её файл. Полноценный отладчик с переходом в исходник библиотеки не добавлен.

## Историческая основа

В [Der Plankalkül, гл. 1 §4e, печатные с. 17–18](https://www.scribd.com/document/493227020/Zuse-Der-Plankalkul-092be0ebdd0784fee570ef37eee273c7) обсуждаются переменные обозначения структур: один и тот же общий план допускает конкретизацию структуры данных. Это историческая опора для параметризации. Каталог, вывод типов и специализация в IL — устройство нашего компилятора, не приписываемый Цузе современный механизм generics. Обозначения списковых операций опираются на гл. 2; литералы и диагностические правила — адаптация диалекта.
