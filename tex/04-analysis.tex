\section{Анализ предметной области}
В данном разделе описаны особенности предметной области работы с базами данных, а также особенностей взаимодействия с целевой базой данных.

\subsection{Описание вычислительного комплекса <<Тераграф>>}
Целевой платформой для кодогенерации инструкций доступа к данным для разрабатываемого ПО является вычислительный комплекс <<Тераграф>>, разработанный в МГТУ им. Баумана.
Комплекс предназначен для эффективного хранения и обработки графовых структур при помощи набора команд дискретной математики DiSC \cite{graph_practicum}.

Подсистема обработки графов включает в себя до 288 гетерогенных вычислительных ядер \texttt{lnh64}, в состав которых входят микропроцессоры двух типов: CPE и SPE.
При этом CPE является универсальным RISC ядром и реализует стандартный набор арифметических команд, а SPE предоставляет набор команд дискретной математики \cite{teragraph}.

Для передачи данных и получения результата от lnh64 применяется библиотека уровня <<ноль>> \texttt{leonhard x64 xrt} \cite{graph_practicum}.
В таблице \ref{tbl:lnh} представлено описание части функций Leonhard API, предоставляемых библиотекой.

\begin{table}[H]

	\begin{tabular}{|c|p{11.5cm}|}
		\hline
		Название & Описание \\ \hline
		lnh\_ins\_sync(str,key,val) & Вставка записи с ключом key и значением val в структуру str \\ \hline

Микроархитектура \texttt{lnh64} поддерживает обращение к семи независимым структурам хранения данных, пронумерованным от 1 до 7 для размещения записей в виде 64-битных целочисленных ключей и значений~\cite{graph_practicum}.

\subsection{Определение минимально необходимого набора операций работы с данными}
Необходимо определить минимальный набор требуемых операций доступа к данным, чтобы определить, поддержку каких операций языка SQL необходимо реализовать при разработке программного обеспечения.

Для обеспечения возможности работы с базой данных необходима поддержка трех основных операций:
\begin{itemize}
	\item Создание структуры хранения данных -- описание набора полей записей, хранимых в БД, соответствует CREATE TABLE в SQL;
	\item Выборка данных -- получение данных из структуры хранения, соответствует SELECT в SQL;
	\item Вставка данных -- загрузка данных в структуру хранения, соответстует INSERT в SQL.
\end{itemize}

Данный набор операций позволяет загружать, удалять и получать данные из БД, что является необходимым для работы с данными, хранящимися в графовой базе данных.

Операции обновления и удаления данных зачастую применяются в рамках более сложной логики проведения расчетов или анализа, поэтому реализация их в общем виде затруднена.

Создание структур хранения данных (таблиц), загрузка в них данных и их выгрузка могут быть описаны единообразно на основе принятых при разработке программных ядер для \texttt{lnh64} и соответствующие SQL-выражения могут использоваться в качестве исходных данных при кодогенерации.

\section{Кодогенерация}
В данном разделе описаны и проанализированы существующие подходы к применению кодогенерации при работе с графовыми базами данных, а также инструменты синтаксического анализа, используемые при кодогенерации.

\subsection{Анализ существующих инструментов синтаксического анализа}
Инструменты кодогенерации применяются при разработке ПО при работе с различными языками программирования. Язык програмирования \texttt{C\#} позволяет создавать пользовательские генераторы кода для создания файлов исходного кода в процессе компиляции \cite{cs_codegen}, а Go поддерживает кодогенерацию на уровне SDK \cite{go_codegen}.

Для генерации инструкций работы с графовой БД необходимо получить абстрактное синтаксическое дерево и произвести синтаксический и лексический анализ SQL выражения.

Существует большое число инструментов, предоставляющих возможности по созданию лексических и синтаксических анализаторов на основе описания грамматик языка.

В таблице \ref{tbl:comp_parsers} приведены результаты сравнительного анализа трех свободно распространяемых инструментов языкового анализа.

На основе проведенного анализа особенностей данных инструментов был сделан выбор в пользу \texttt{ANTLR}, поскольку он обеспечивает единообразие описания грамматик лексического и синтаксического анализаторов, а также основан на LL(*) анализаторах, предоставляющих баланс между эффективностью работы и мощностью задаваемого набора грамматик \cite{ll_parsers}.

В официальных интернет-ресурсах \texttt{ANTLR} размещены ссылки на репозитории, содержащие разработанные сообществом грамматики для разных языков, в том числе и для множества разновидностей SQL \cite{antlr_grammars}.

\subsection{Анализ существующих аналогов}
При рассмотрении инструментов, входящих в экосистему систем хранения и обработки графов \texttt{Neo4j} \cite{neo4j} и \texttt{Apache TinkerPop} \cite{apache_tinkerpop} выявлено, что работа в них производится с применением специализированных языков высокого уровня, спроектированных специально для обработки данных, которые транслируются в SQL, либо другие наборы инструкций для взаимодействия с основной базой данных.

Также метод кодогенерации NoSQL запросов к базе данных из SQL-выражений применяется для обеспчения работы устаревшего программного обеспечения с современными NoSQL базами данных.
При этом реализация преобразования запросов оказывается эффективнее реализации драйвера к NoSQL базе данных \cite{sql_to_nosql}.

Вычислительный комплекс <<Тераграф>> требует составления обработчиков запросов на языке \texttt{C++} и использования программной библиотеки \texttt{leonhard x64 xrt} \cite{graph_practicum}.
Такой подход вызывает сложности у новых пользователей системы в силу необходимости углубленного знания языка \texttt{C++} и низкоуровневых деталей взаимодйествия с системой и принятых в ее экосистеме шаблонов программирования.

Предлагается применить метод кодогенерации для преобразования выражений на языке запросов SQL, широко используемого при работе с базами данных, в текст на языке \texttt{C++}, реализующий запрошенные операции работы с данными в виде обертки вызовов функций библиотеки \texttt{leonhard x64 xrt}.

\section{Анализ процесса кодогенерации}
На вход процесса кодогенерации инструкций работы с данными поступает текст SQL-выражения, результатом процесса является код на языке \texttt{C++}, осуществляющий работу с данными при помощи базовых библиотечных функций набора команд дискретной математики DiSC.

В процессе синтаксического анализа входного SQL-выражения используется грамматика языка SQL, на основе которой при помощи \texttt{ANTLR} построены лексический и синтаксический анализаторы.

SQLite является самым используемым ядром баз данных \cite{sqlite_mostused} и широко используется на пратике, что позволяет предположить оптимальность и корректность реализованных в нём алгоритмов.
Поэтому для получения алгоритмов обхода структуры хранения данных предлагается использовать дублирование запросов к встраиваемой базе данных SQLite и анализ байткода плана получившихся запросов.
Для этого потребуется поддерживать соединение с локальной базой данных SQLite, которая будет создана на время сессии кодогенерации.

Первым этапом обработки входного SQL-выражения является его преобразование в абстрактное синтаксическое дерево путем применения к нему лексического и синтаксического анализаторов, основанных на грамматике языка SQL.

Вторым этапом происходит обход полученного абстрактного синтаксического дерева и формирование на его основе набора данных, необходимых для получения кода на языке \texttt{C++}.

На последнем этапе преобразования происходит сборка текста на основе полученных ранее данных, а также обновление состояния сохраненного контекста кодогенерации в базе данных SQLite.
База данных также используется для получения алгоритма выборки данных из хранилища, при этом в соответствие операциям байткода SQLite ставятся операции языка \texttt{C++}.

\section{Требования к программному обеспечению}
Программа должна предоставлять разработчикам возможность преобразования SQL-подобных предложений в инструкции на языке \texttt{C++} для следующих операций:
\begin{itemize}
	\item Создание таблицы;
	\item Выборка данных;
	\item Вставка данных.
\end{itemize}

Данные операции должны быть реализованы в виде сформированной структуры и набора методов или функций, позволяющих клиентскому коду взаимодействовать с графовым хранилищем данных.

Необходимо реализовать поддержку вызова процедур преобразования SQL-выражений в сторонних утилитах, обеспечивающих вставку сгенерированных выражений в файлы исходного кода.
Это позволит интегрировать разработанное программное обеспечение в конвейер разработки и трансляции программ, взаимодействующих с целевой платформой.

Требуется реализовать интерфейс командной строки, который обеспечит возможность интерактивно генерировать код на основе вводимых SQL-выражений, а также предусмотреть возможность стороннего вызова разработанного программного модуля для встраивания сгенерированного программного кода в файлы исходного кода на \texttt{C++}.
