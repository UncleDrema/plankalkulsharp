# PlankalkulSharp

Учебный компилятор линейной нотации Plankalkül в .NET CIL и Windows-монитор исполняющей среды. Каждый запуск выполняется в отдельном .NET-процессе с собственной неуправляемой кучей. Компилятор остаётся на Python; общая библиотека .NET предоставляет память, проверки ссылок и управление выполнением.

## Требования

- Python 3.14+
- [uv](https://docs.astral.sh/uv/)
- .NET SDK 10

Версию SDK выбирает `global.json`: используется установленный стабильный .NET 10, даже если рядом установлен .NET 11 Preview. То же правило поставляется с Python-пакетом и применяется в кешах и временных каталогах сборки.

Для сборки IL используется `Microsoft.NET.Sdk.IL` версии `10.0.0-preview.2.25163.2`. Java и ANTLR 4.13.2 нужны только для повторной генерации парсера.

## Быстрый старт

### VS Code

Расширение в [`vscode/`](vscode/README.md) добавляет LSP для `.pk`, нотацию рядом с редактором, справку, стандартные планы и монитор исполнения/памяти. Установите локальный `vscode/plankalkulsharp-0.1.0.vsix` через **Extensions: Install from VSIX…** и откройте этот проект после `uv sync`. Интерпретатор `.venv` выбирается автоматически; другой путь задаётся в `plankalkul.python`.

Основные команды: **Plankalkül: Нотация рядом**, **Plankalkül: Запустить программу**, **Plankalkül: Монитор запусков**. Аргументы для примера списка — `[5,3]`. Сборка использует снимок буфера и не перезаписывает исходник. [План и журнал переноса](docs/vscode-plan.md).

### Самостоятельное окно WPF

```powershell
uv sync
uv run plankalkulsharp machine examples/reverse_list.pk
```

Слева доступны файлы папки, недавние `.pk` и история запусков. Код и нотация расположены рядом; панель памяти можно скрыть. Стандартные планы и справка с поиском открываются в том же окне. Ctrl+O открывает файл, F5 запускает программу, F1 открывает справку. Python выбирается в меню «Настройки».

В окне машины задайте аргументы `5 3` и нажмите «Запустить». Для наблюдения за узлами задайте задержку, затем нажмите «Пауза»: можно выбрать объект и просмотреть его поля и ссылки. Исходники имеют единое расширение `.pk` и открываются только для чтения. Подробнее — [устройство машины](docs/machine.md).

Запуск без интерфейса:

```powershell
uv run plankalkulsharp run examples/reverse_list.pk -- 5 3
```

Команда печатает `2`: создаётся список `1 → 2 → 3 → 4 → 5`, он разворачивается, и программа возвращает значение узла после узла со значением `3`.

| Вход | Результат |
| --- | --- |
| `5 1` | `0` |
| `5 3` | `2` |
| `1 1` | `0` |

Второй аргумент — значение искомого узла. Для `N < 1` или значения вне `1..N` пример возвращает `-1` и не выделяет память.

## Команды

```powershell
# AST и семантический анализ
uv run plankalkulsharp parse examples/reverse_list.pk
uv run plankalkulsharp analyze examples/reverse_list.pk

# Только IL: build/reverse_list.il или заданный путь
uv run plankalkulsharp compile examples/reverse_list.pk
uv run plankalkulsharp compile examples/reverse_list.pk -o output/ReverseList.il

# Сохранить собранный программный модуль
uv run plankalkulsharp build examples/reverse_list.pk -o build/list
uv run plankalkulsharp build output/ReverseList.il -o build/from-il

# Временная .NET-сборка и запуск
uv run plankalkulsharp run --heap-size 1048576 --memory-trace examples/reverse_list.pk -- 5 3
```

`compile` создаёт только `.il`. `build` сохраняет DLL модуля, а `run` собирает её временно, передаёт общему Worker и удаляет каталог после его завершения. Размер кучи по умолчанию — 1 МиБ; `--heap-size` принимает положительное число байтов, кратное восьми и не больше `2147483647`. `--memory-stats` печатает итоговую статистику кучи в stderr. `--memory-trace` печатает операции кучи в stderr и включает статистику. Вывод программы остаётся в stdout. Код завершения: 0 — успех, 1 — ошибка, 130 — остановка пользователем.

Worker и Runtime собираются один раз в пользовательский кеш. WPF собирается отдельно при вызове `machine`; для обычного CLI интерфейс не требуется. Изменение ресурсов компилятора или среды сборки создаёт новый кеш. Runtime не пересобирается и не копируется в каталог каждой программы.

Собранные программы тоже кешируются на уровне Python-компилятора. `build`, `run` и запуск из WPF повторно используют DLL, если совпадают сгенерированный IL (включая хеш исходника), Runtime и среда сборки. Аргументы, размер кучи и задержка не требуют пересборки. Кеш сохраняется между открытиями машины; в каталог конкретного запуска копируются готовые выходные файлы. Первый запуск ещё может требовать сборки .NET и загрузки зависимостей, повторный не вызывает `dotnet build` для неизменившегося модуля.

Программная DLL — библиотека с `Execute` и `GetMetadata`, которую загружает Worker. Прямой вызов `dotnet PlankalkulProgram.dll` не поддерживается. `build --json` возвращает путь к модулю и Worker; ручной запуск имеет вид `dotnet <workerPath> --module <assemblyPath> -- 5 3`. Для сборки IL вне CLI шаблону нужно передать `PlankalkulRuntimePath` — абсолютный путь готовой Runtime DLL рядом с Worker. Старые исполняемые IL/DLL нужно пересобрать из `.pk`.

## Списки и стандартная библиотека

`n x T` и `* x T` — фиксированные и переменные списки. Литералы: `[1,2]`, `[]`, `(7,9)` для записи. Составные значения копируются рекурсивно; изменение копии больше не меняет прежний массив. Равенство структурное. Ссылки `@` внутри значений сохраняют свою идентичность.

```powershell
uv run plankalkulsharp run examples/lists.pk -- '[2,3,4]'
```

Аргументы CLI — значения JSON, каждый отдельным аргументом. В WPF можно ввести `[2, 3, 4]` прямо в поле аргументов. Тип параметра отличает список от записи; каждый результат печатается отдельной строкой, составные — JSON-массивами.

`N` возвращает длину, `Lz` соединяет списки. `Qz`, `Sp`, `Nr`, `insert`, `remove`, `reverse` реализованы стандартными `.pk`-планами с внутренней специализацией типов. Кнопка «Стандартные планы» показывает их исходники и нотацию. Подробности, ограничения производительности и расширение библиотеки — в [спецификации](docs/lists.md).

## Ссылки и динамическая память

`@T` означает ссылку на объект именованного типа `T`, а выражение `@T` выделяет нулевой объект этого типа. `NIL` — пустая ссылка. В компонентном пути `@` разыменовывает ссылку:

```text
node = (32.0, @node)
@node => Z0
7 => Z0[@.0]
NIL => Z0[@.1]
Z0 => @
```

Присваивание, аргументы и результаты копируют ссылку. `=> @` освобождает один объект; связанные объекты освобождаются явно. Разыменование `NIL`, освобождённой ссылки или нехватка кучи завершают программу с диагностикой. Полные правила, представление данных и ограничения описаны в [документе о динамической памяти](docs/dynamic-memory.md).

## Историческая нотация в мониторе

Индексные циклы записываются как `W1 i0 (n) { ... }`; доступны W1–W5 и прежний W. Индексы `i` доступны только для чтения в теле цикла. `FIN` и `условие => FIN2` завершают заданное число вложенных областей. FOR удалён; [правила циклов, Fin и миграция](docs/loops.md).

Панель «Нотация Plankalkül» рядом с исходником показывает проверенный AST в строках V/K/S: компоненты массивов и записей, вызовы процедур и вложенные блоки. Пустая K скрывается, необходимые скобки сохраняют порядок вычислений. Нажатие на формулу переводит к исходнику; позиция выполнения подсвечивается. Для знакомства откройте `examples/notation.pk`. Кнопка «Справка по языку» открывает встроенное описание конструкций с оглавлением и примерами; «К программе» возвращает рабочий экран, сохраняя его состояние.

Правила отображения, источники и отличия от оригинала описаны в [документе о визуализации](docs/notation-view.md). Конструкции нашего расширения выделены охрой.

## Устройство и проверка

Правила новых списков и расширяемых шаблонов: [списки и стандартные планы](docs/lists.md). [План и статус выполнения](docs/lists-stdlib-plan.md) сохраняют решения и результаты проверок.

```text
grammar/Plankalkul.g4                  грамматика ANTLR
examples/reverse_list.pk                 пример динамического списка
src/plankalkulsharp/plankalkul_ast/     AST
src/plankalkulsharp/frontend/            ANTLR-парсер и построение AST
src/plankalkulsharp/dotnet_assets/       IL-проект, Runtime, Worker и WPF-монитор
src/plankalkulsharp/semantic/             типы и семантический анализ
src/plankalkulsharp/codegen/              генерация CIL
tests/                                    проверки компилятора, кучи и CLI
```

```powershell
uv run pytest
```

Сквозные проверки требуют .NET SDK; их пропуск не подтверждает работоспособность запуска. Интерфейс проверяется на Windows с настоящим окном WPF; проверка Linux/macOS не заявляется. Исторические материалы в `docs/` (кроме `dynamic-memory.md`, `machine.md`, `notation-view.md` и `loops.md`), `tex/` и `habr/` сохранены как контекст. Фактическое поведение задают грамматика, исходный код компилятора, рантайм и пример.

Точка входа надёжно принимает только скалярные `int32`; `int64` и составные аргументы пока не поддерживаются надёжно. Также известны ошибка конструктора `BoolLiteral` для литералов последовательностей бит и неработающая генерация кода для их компонентов.

Для обновления сгенерированного парсера после изменения грамматики:

```powershell
uv run python scripts/generate_parser.py
```
